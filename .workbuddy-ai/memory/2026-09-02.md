### Two probe bugs worth remembering (cost me a full re-run)

1. **`getComputedStyle` returns `oklch(...)` unresolved** — regexing the numbers
   out of it and treating them as RGB produced nonsense (`rgb(0,0,220)`).
   Correct method: paint the computed value into a 1x1 canvas and read back
   `getImageData` — Chromium resolves oklch → sRGB for you.
2. **`pg.evaluate(fn, [a, b])` passes ONE argument.** A `(sel, prop) => ...`
   signature silently gets `sel = [a,b]`, `prop = undefined`. Pass an object:
   `pg.evaluate(fn, {"sel": s, "prop": p})` and destructure inside.

Also: measuring lazy images right after a scroll sweep gives false
"broken" results. Poll `complete && naturalWidth > 0` up to ~8s before
declaring failure.

## v3.3 — photos showing as placeholders: REAL root cause (webP, not team.js)

Ali reported placeholders again. It was **not** the old `team.js` race — that was
genuinely fixed. The real cause only reproduces on the preview server.

### The bug

The WorkBuddy preview server (`127.0.0.1:<port>/static-html/<hash>/`) has an
extension whitelist. Verified with urllib:

```
index.html                     200
css/tokens.css                 200
assets/logo.png                200   8,301 B
assets/team/ceo.jpg            200  60,192 B
assets/team/ceo.webp           404          <-- 34 KB file, exists on disk
assets/projects/parsa-tower.jpg  200  99,487 B
assets/projects/parsa-tower.webp 404
```

Every photo used `<picture><source srcset="*.webp"><img src="*.jpg"></picture>`.
Chromium picks the first matching `<source>`; **if that request fails it does
NOT fall back to the `<img src>`**. So all 34 photos rendered as empty boxes.
`logo.png` was a plain `<img>` with no `<picture>` — which is why the logo showed
and nothing else did.

Invisible under `file://` because everything loads there. My earlier "36/36 OK"
verification was real but tested the wrong transport.

### The fix

- Stripped all 14 `<picture>`/`<source>` wrappers (7 in `index.html`, 7 in
  `about.html`) → plain `<img src="*.jpg">`.
- `js/projects.js` `mediaHTML()` now emits a plain `<img>` (was `<picture>`).
- `about.html` L102 CEO photo had a bare `.webp` src → switched to `.jpg`.
- Verified over HTTP: **36/36 images load**, 0 broken.

### Bonus fix found while investigating — fonts were never loading

The preview server's CSP blocks `fonts.googleapis.com`. `document.fonts` had
**zero** registered faces; the whole site was rendering in a fallback face.
Self-hosted Vazirmatn:

- Downloaded the Google CSS with a Chrome UA (needed to get woff2 + unicode-range).
- 3 woff2 subsets → `assets/fonts/vazirmatn-{0,1,2}.woff2` (~100 KB total).
- Rewrote URLs to local paths → `css/fonts.css` (subsets + unicode-range kept).
- Linked `css/fonts.css` first in all 4 pages; deleted the 3 Google `<link>`s
  (preconnect x2 + stylesheet).
- Verified: 8/12 faces loaded (rest are on-demand subsets), `h1` resolves to
  Vazirmatn. woff2 is served 200 by the preview server.

### Rules for future work here

1. **Verify over the preview HTTP URL, never `file://`.** They behave differently
   and `file://` hides real breakage.
2. **Never wrap photos in `<picture>` with a `.webp` source** in this project.
3. **Never `<link>` to a font CDN** here — CSP blocks it; self-host instead.
4. When a user reports something you measured as fine, suspect the transport
   before suspecting the code.

### Tooling notes

- Piping a long Playwright run through `tail` buffers all output until exit —
  looks like a hang. Print with `flush=True` and don't pipe, or use
  `run_in_background` + notification.
- A polling loop (`while pending: wait 200ms`) over HTTP hung ~8 min. A hard-capped
  scroll + fixed `wait_for_timeout(2500)` settle finished in 29s. Prefer the latter.

## v3.3 follow-up — preview panel kept showing placeholders

Ali reported placeholders a third time, 2026-09-03. The server was already
returning correct HTML; my pixel analysis (screenshotting each `.member__photo`
and computing colour SD + unique-colour count) confirmed all 34 photos render
as real photographs — lumSD 60-93, 33k-67k unique colours per region. Even
read the CEO portrait back as an image — it's the real photo.

So the problem was **not** the code, the served HTML, or even the WorkBuddy
preview server's HTTP — it was the preview panel holding stale state. Three
confirmations in a row were being trusted to mean "the fix is deployed" when
the user was still looking at the broken first response.

### What I did

Started a local `serve.py` (ThreadingHTTPServer subclass):
- Serves `naji-sazan-amin/` on `127.0.0.1:8777` (loopback only).
- MIME map includes `.webp`, `.woff2`, `.jpg`, etc. — none of which the
  WorkBuddy preview server's whitelist knew about.
- `Cache-Control: no-store, must-revalidate, max-age=0` + `Pragma: no-cache` +
  `Expires: 0` on every response — kills the whole caching chain.
- Started in background; `present_files` opens the four pages via the
  localhost URL directly.

That port is free on this box, but verify with `connect_ex(('127.0.0.1', p))`
first. Server stays running; `python serve.py [port]` to launch.

### Rules, updated

1. **`present_files` with local HTML files is not a verification — it is a
   preview of whatever the preview panel happens to be holding.** Use a localhost
   server with `no-store` to deliver fresh content; use pixel-level checks
   (`screenshot + PIL statistics.pstdev`) to verify visuals. `complete` /
   `naturalWidth` are necessary but not sufficient.
2. **The visual is the verification.** I read the CEO screenshot back as an
   image — that's the only check that matches what Ali sees. Pixel statistics
   are a proxy when reading isn't available, but reading is available.
3. **Three "all good" reports in a row while the user keeps seeing placeholders
   is a measurement bug, not a coding bug.** Stop, change the measurement.

### Tooling note

A polling loop (`while pending: wait 200ms`) inside Playwright over HTTP
**hangs indefinitely** — never saw it return 0 within any timeout. Replace
with a hard-capped scroll + single fixed `wait_for_timeout(2500-3000)` settle.
Verified: 29 s vs indefinite hang.
